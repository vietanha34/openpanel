# T4 — Event Analytics Tree Table + Toolbar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the flat Analytics table with a lazily-expanding tree table (event → property key → value → nested key → value) plus its toolbar, driven by the four Wave 0 tRPC procedures.

**Architecture:** One pure module (`tree-utils.ts`) holds every decision that can be tested without React: path building, indent, icon, badge, level/expandability rules, and the number formatters with their zero guards. Two React modules render on top of it — `event-tree-table.tsx` owns toolbar state (sort, search, pct, selection) plus the root `eventAnalyticsList` infinite query and the totals row; `tree-nodes.tsx` holds the recursive node components, each owning its own `useInfiniteQuery` gated by `enabled: expanded`, so a failing node shows an inline retry without breaking the rest of the tree.

**Tech Stack:** React 19, TanStack Router/Query (`useInfiniteQuery`), tRPC client via `@/integrations/trpc/react`, existing UI primitives in `@/components/ui/*`, `lucide-react` icons, Tailwind v4. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-09-15-event-analytics-tree-design.md` (sections 3 and 4 binding; task prompt for T4 in §8)

**Design source:** Claude Design project `233791a0-310f-443c-8118-b345c9f77b7d`, file `EventAnalyticsScreen.dc.html` (read in full, 59,803 chars). The `flatten()` method there is the behavioural reference.

### Two different "depths"

The design indents by *visual* depth; the contract limits by *logical* level. They differ under an `obj` node, because `prefix` narrowing does **not** consume a `parentPath` entry.

| Node | Logical level | Query that produces it | parentPath length |
|---|---|---|---|
| event | 0 | `eventAnalyticsList` | — |
| property key (`kind: 'key'`) | 1 | `eventPropertyKeys(prefix: '')` | 0 |
| object node (`kind: 'obj'`) | 1 | same call | 0 |
| key inside an object | 1 | `eventPropertyKeys(prefix: 'payload.')` | 0 |
| value of a level-1 key | 2 | `eventPropertyValues` | 0 |
| nested key under a value | 3 | `eventPropertyKeys(parentPath: [{key,value}])` | 1 |
| value of a nested key | 4 | `eventPropertyValues(parentPath: [{key,value}])` | 1 |

Visual indent still uses the render depth (`depth * 22px`), exactly like the design, so an object's children sit one step further right even though they stay at logical level 1.

Chevron rule: a node shows a chevron only when the children it would load stay within level 4. A level-4 value has no chevron (spec §6: "Depth > 4: chevron hidden").

- `import type` only, so the file runs under vitest without the `@/` alias.
- `MAX_LEVEL` must equal `EVENT_ANALYTICS_MAX_DEPTH` (4) from the contract; the comment should say so.

```ts
import type {
  IEventAnalyticsMetricRow,
  IEventAnalyticsPropertyType,
  IEventAnalyticsSortDir,
  IEventAnalyticsSortKey,
} from '@openpanel/validation';

export const INDENT_PX = 22;

/** Mirrors EVENT_ANALYTICS_MAX_DEPTH in packages/validation/src/event-analytics.ts. */
export const MAX_LEVEL = 4;

const DASH = '—';

const countFormatter = new Intl.NumberFormat('en-US');

export type TreeNodeKind = 'event' | 'key' | 'obj' | 'value' | 'leaf';

const ICONS: Record<TreeNodeKind, string> = {
  event: 'E',
  key: 'K',
  obj: '{}',
  value: 'V',
  leaf: '·',
};

export function childPath(parentPath: string, id: string) {
  return `${parentPath}/${id}`;
}

export function indentStyle(depth: number) {
  return { paddingLeft: `${depth * INDENT_PX}px` };
}

export function iconFor(kind: TreeNodeKind) {
  return ICONS[kind];
}

export function badgeFor(
  kind: TreeNodeKind,
  type: IEventAnalyticsPropertyType,
) {
  if (kind === 'obj') {
    return 'object';
  }
  // Events carry no category in the backend contract, so they get no badge.
  if (kind !== 'key' || type === 'unknown') {
    return null;
  }
  return type;
}

export function canExpand(childLevel: number) {
  return childLevel <= MAX_LEVEL;
}

export function valueKindForLevel(level: number): 'value' | 'leaf' {
  return level >= MAX_LEVEL ? 'leaf' : 'value';
}

export function formatCount(value: number) {
  return Number.isFinite(value) ? countFormatter.format(value) : DASH;
}

export function formatEventsPerUser(row: IEventAnalyticsMetricRow) {
  if (row.users <= 0) {
    return DASH;
  }
  return (row.events / row.users).toFixed(2);
}

export function formatPercent(part: number, total: number) {
  if (total <= 0 || !Number.isFinite(part)) {
    return DASH;
  }
  return `${((part / total) * 100).toFixed(2)} %`;
}

export function subPercent(part: number, total: number, showPct: boolean) {
  return showPct ? formatPercent(part, total) : null;
}

export function nextSort(
  current: { sort: IEventAnalyticsSortKey; dir: IEventAnalyticsSortDir },
  clicked: IEventAnalyticsSortKey,
): { sort: IEventAnalyticsSortKey; dir: IEventAnalyticsSortDir } {
  if (current.sort !== clicked) {
    return { sort: clicked, dir: 'desc' };
  }
  return { sort: clicked, dir: current.dir === 'desc' ? 'asc' : 'desc' };
}

export function sortArrow(
  current: { sort: IEventAnalyticsSortKey; dir: IEventAnalyticsSortDir },
  column: IEventAnalyticsSortKey,
): '↓' | '↑' | '' {
  if (current.sort !== column) {
    return '';
  }
  return current.dir === 'desc' ? '↓' : '↑';
}
```

5. `PropertyKeyNode`:

   - `kind === 'key'` → icon `K`, badge from `badgeFor`; expanding renders a `PropertyValuesBranch`.
   - Checkbox is rendered when `depth <= 1`; its path is `childPath(eventPath, key)`.
6. `PropertyValuesBranch` — `useInfiniteQuery(trpc.overview.eventPropertyValues.infiniteQueryOptions({ ...input, event, key, type, parentPath, sort, dir, limit: 5 }, { enabled: expanded, initialCursor: 0, getNextPageParam: (last) => last.nextCursor }))`. Renders one `PropertyValueNode` per row, and when `hasNextPage` a `LoadMoreRow` labelled ``Load 5 more values · ${formatCount(remaining)} remaining`` using `remaining` from the **last** loaded page.
7. `PropertyValueNode` — icon from `valueKindForLevel(level)`. It can expand only when `canExpand(level + 1)` **and** `parentPath.length < EVENT_ANALYTICS_MAX_PARENT_PATH`; expanding renders a `PropertyKeysBranch` with `prefix=""` and `parentPath={[{ key, value }]}` at logical level 3. A level-4 value therefore shows no chevron, which is spec §6.
8. `NodeErrorRow` — when a branch query `isError`, that branch renders a single inline row with the error message and a `Retry` button calling `refetch()`. No `throw`, so sibling branches keep working.
9. Every branch shows a one-line `Loading…` row while `isLoading`.
